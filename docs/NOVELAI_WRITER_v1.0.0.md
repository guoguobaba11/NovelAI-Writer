# NovelAI Writer · 产品白皮书

> **版本：v1.0.0**（文档发布版）| 内部构建号 1.19.9 | 2026-07
>
> 「让 AI 写出真正连贯的长篇小说——保证事件链、时间顺序、人物性格、逻辑、信息把控的五维一致性。」

---

## 一、产品理念

### 1.1 解决什么问题

长篇小说（几十万到数百万字）的创作中，**一致性崩塌**是最大痛点：

- 第 3 章死掉的角色在第 18 章「复活」
- 第 5 章角色已知道某秘密，第 10 章却表现得一无所知（信息泄漏）
- 人物性格在第 20 章后开始「漂移」，与开篇人设矛盾
- 伏笔埋了不收，或提前揭晓，或因果倒置
- 时间线混乱，事件先后矛盾

NovelAI Writer 把这些一致性约束**结构化进数据库**，让 AI 在每次生成/修改时都能「看见」全局约束，从而输出连贯的内容。

### 1.2 核心设计哲学

| 原则 | 说明 |
|------|------|
| **五维一致性** | 事件链（因果）、时间顺序、人物性格、逻辑、信息把控——所有功能围绕这五个维度 |
| **结构化知识库** | 不是把全文丢给 AI，而是抽取事件/人物/伏笔/事实入库，AI 基于结构化上下文工作 |
| **人机协作而非替代** | AI 出方案/草稿，作者审阅批准；计划模式逐项确认；按段采纳 diff |
| **启发式 + LLM 双层** | 先用秒级启发式扫描找硬伤，再用 LLM 做深度分析和修改建议 |
| **本地优先** | 数据存在本地 SQLite，AI 调用走用户自己的 API key，无云端依赖 |

### 1.3 适用场景

- 已有初稿（Markdown 手稿），想用 AI 辅助修改打磨
- 想保证长篇连载的角色/情节/伏笔一致性
- 需要 AI 编辑器做段落级润色、一致性检查、风格统一

## 二、技术架构

### 2.1 技术栈

| 层 | 技术 | 说明 |
|----|------|------|
| 后端 | Python + FastAPI + Uvicorn | 86 个 REST/WebSocket 端点，同步阻塞式（桌面应用足够） |
| 数据库 | SQLite（WAL 模式） | 18 张表，纯文件部署，零配置 |

## 三、核心功能

### 3.1 知识库（五维一致性的基础）

所有一致性保证建立在结构化知识库之上：

| 维度 | 数据表 | 作用 |
|------|--------|------|
| **事件链** | `event` | 每章的事件（含因果 `cause_event_ids`、时间戳、参与者、重要度） |
| **时间顺序** | `chapter.story_time_start/end` + `event.story_time` | 故事内时间轴，扫描时间矛盾 |
| **人物性格** | `character`（MBTI/认知栈/九型/弧光/baseline关键词） | 性格基准，检测漂移 |
| **逻辑** | `character_milestone` + `relationship_evolution` | 成长里程碑 + 关系演变时间序列 |
| **信息把控** | `fact`（含 `known_by` 谁知道约束 + `reliability` 可靠度） | 防信息泄漏（角色不该知道的事） |

**关键设计：`fact.known_by`**——每个事实标注「哪些角色知道」，AI 生成 POV 视角章节时，只会使用该角色「已知」的事实，杜绝信息泄漏。

### 3.2 AI 编辑器（核心写作工作台）

三栏布局（左：章节列表/诊断/要点 | 中：正文编辑 | 右：要点/批注/AI面板）：

| 功能 | 说明 |
|------|------|
| **AI 流式改稿** | 输入指令（如"把第三段对话改得更口语化"），AI 流式输出，按段落采纳 |
| **按段采纳 diff** | AI 输出按段落切分为卡片，每段独立 ✓采纳/✗拒绝，支持 Web Worker diff 高亮 |
| **计划模式**（OpenCode 风） | AI 先列出修改清单（what/why/where/severity），逐项批准/跳过，顶部进度条实时显示 X/N |
| **选区 AI 改** | 选中文字→浮按钮→只改选区（inline 模式），AI 输出拼回原位置 |
| **今日简报** | 硬关联（上一章/本章位置/人物/伏笔）+ LLM编辑建议 + 自动疑点扫描 |
| **硬校验** | 秒级启发式扫描本章（信息泄漏/时间线/死人复活），无需 AI |
| **查找替换** | Ctrl+F/H，区分大小写，支持正则 |
| **撤销/重做** | Ctrl+Z / Ctrl+Shift+Z，完整 undo/redo 栈 |
| **版本树** | 每次 AI 改稿/保存自动建版，增量 patch 存储（difflib），可命名存档/恢复/对比 |
| **章节目标** | 每章可设目标字数，顶栏进度条实时显示 |
| **自动保存** | 30秒无操作自动保存 |

### 3.3 一致性扫描（4 套启发式，秒级）

不依赖 AI，纯规则，秒级出结果：

| 扫描器 | 检测内容 |
|--------|----------|
| **伏笔扫描** `threads` | 烂尾（planted未resolved）、超期（超过全书85%未揭晓）、提前揭晓（payoff在planted之前）、abandoned但暗示重要 |
| **逻辑链扫描** `logic` | 死人复活（status=死后仍出场）、因果倒置（cause在effect之后）、地点冲突（同时异地无过渡）、信息泄漏（角色知道不该知道的事）、链断裂（相邻章节事件无关联） |
| **文风漂移** `style` | 句长/独白比例/描写密度/感叹号的章节间 z-score（与基线前N章比，超阈值报漂移） |
| **性格漂移** `personality` | 人物 MBTI baseline 关键词与实际表现的偏差 |

### 3.4 LLM 优化建议

5 类 AI 优化，基于知识库 + 扫描结果出可执行建议：

| 类型 | 说明 |
|------|------|
| **性格优化** | 针对某人物的 MBTI/认知栈调整建议 |
| **弧光优化** | 人物成长曲线（starting_point→catalyst→crisis→climax→resolution）优化 |
| **关系优化** | 某对人物的关系演变（亲密度/信任/冲突）优化 |
| **全局优化** | 扫描全本给综合建议 |
| **结构优化** | 起承转合/3幕/重要性曲线的叙事结构建议 |

每条建议带 `priority`(high/medium/low) + `chapter_focus`(应用章节范围) + `evidence`(数据依据) + 状态管理(open/applied/dismissed)。

### 3.5 可视化（7 个 ECharts 图表）

| 图表 | 类型 | 展示 |
|------|------|------|
| **时间线** | custom+scatter | 故事内时间轴：章节条 + 事件点 + 伏笔标记 |
| **事件因果链** | graph(力导向) | 节点=事件，边=cause关系 |
| **节奏曲线** | bar+line | 每章字数/事件数/伏笔推进/一致性high问题 |
| **MBTI矩阵** | heatmap | 人物 MBTI 兼容度热力图 |
| **成长线** | 纯DOM | 人物弧光进度条 + 里程碑 |
| **亲密度曲线** | line(多图) | 每对关系的亲密度/信任/冲突演变 |
| **关系网** | graph(力导向) | 人物关系拓扑图 |

### 3.6 修改流水线（Pipeline）

3 阶段串联全工具：

1. **Stage 1 快速诊断**（秒级）：4 套扫描 + 结构分析 → 健康度快照
2. **Stage 2 智能合并**（秒级）：跨扫描器去重 + 按优先级排序 → 修改路线图
3. **Stage 3 LLM 优化**（5-15分钟）：5 类 AI 优化建议

### 3.7 叙事结构分析

- **起承转合** 4 段（setup/development/climax/resolution）分布
- **3 幕结构**（建置/对抗/结局）章节划分
- **重要性曲线**（事件重要度沿故事位置的分布 + 高潮定位）
- **问题检测**：转折点缺失、前重后轻、连续塌陷、卷间断档、伏笔铺设失衡

## 五、安装与使用

### 5.1 桌面版（推荐）

1. 获取 `NovelAI Writer.exe`（单文件，24MB）
2. 双击运行 → 自动在同目录生成 `.env` 模板
3. 填入 API key（推荐 DeepSeek，便宜量大）：
   ```ini
   NOVELAI_PROVIDER=openai_compatible
   NOVELAI_BASE_URL=https://api.deepseek.com
   NOVELAI_API_KEY=sk-你的key
   NOVELAI_MODEL=deepseek-chat
   ```
4. 重启 exe → 桌面窗口打开（固定 2520×1680）
5. Windows Defender 拦截 →「更多信息」→「仍要运行」

### 5.2 开发模式

```bash
pip install -r requirements.txt
python run.py web        # 浏览器模式 http://127.0.0.1:8765
python desktop.py        # 桌面窗口模式
```

### 5.3 推荐工作流

1. **导入**：把 MD 手稿（`# 卷头` / `## 回头` 格式）拖入窗口或点导入
2. **建库**：给主要人物标 MBTI（建库→MBTI标注），录入关键事实/关系
3. **扫描**：跑全本扫描，看一致性硬伤
4. **AI抽取**：让 AI 自动从正文抽取事件/伏笔入库
5. **编辑**：在 AI 编辑器里逐章修改（计划模式/按段采纳/今日简报）
6. **优化**：让 AI 给性格/弧光/关系优化建议
7. **导出**：导出 .docx / .md

- 无在线协作/云同步（本地优先设计）

### 7.4 已解决的限制（v1.0.0）

| 原限制 | 解决方案 |

| AI 端点错误处理 | optimize/extract/analyze/pipeline-quick 共 10 个端点全部加 try/except + `_ai_error()` 统一降级，AI 故障返回结构化错误而非 500 |
